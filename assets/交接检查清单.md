# <项目名称> 研发交接与发布检查清单

## A. 资产接收

- [ ] 仓库、基线分支/Commit、制品版本可定位
- [ ] 构建和启动说明经非原作者复现
- [ ] 环境、配置项和 Secrets 交付方式明确（文档中无明文密钥）
- [ ] 测试账号、角色和种子数据可获得
- [ ] 原始需求、原型、设计、接口和数据资料齐全
- [ ] 第三方账号、额度、合同、许可证及 Owner 明确
- [ ] 已知缺陷、Mock、硬编码、TODO 和技术债已登记

## B. Development Ready

- [ ] MVP 基线审计通过
- [ ] In/Out/Later 和 Must/Should/Could/Won't 已确认
- [ ] 所有 Must 需求有来源、Owner、目标版本和 AC
- [ ] 核心流程、异常、状态、权限、API、数据已明确
- [ ] 必要 NFR 有场景、阈值、口径、环境和验证方法
- [ ] 安全、隐私、合规、可访问性已判断适用性
- [ ] 迁移、兼容、第三方和环境依赖有 Owner
- [ ] 核心待确认项为零；其他待确认项有 Owner/日期/阻塞级别
- [ ] C 技术负责人确认可估算；QA 确认可设计测试

结论：`READY / READY WITH ACCEPTED RISKS / NOT READY`

## C. Definition of Done

- [ ] 代码评审、自动化测试和必要专项测试通过
- [ ] Req ID → AC → Test → 证据双向可追踪
- [ ] 接口、数据字典、架构/ADR、用户与运维文档同步
- [ ] 新增技术债和例外均登记并由具名责任人接受
- [ ] 埋点、日志、指标、追踪、Dashboard 和告警可用
- [ ] 性能、容量、安全、兼容、迁移/恢复目标有证据
- [ ] 无未处置的阻塞/严重缺陷；例外有期限和复审条件

- [ ] 内部项目：业务 Sponsor/PO 与运营 Owner 接受
