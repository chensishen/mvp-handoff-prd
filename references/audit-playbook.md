# MVP 逆向审计手册

## 审计原则

先观察，后判断；先记录当前事实，后讨论目标。功能存在性、完成度和生产就绪度是三件不同的事。

## 建议顺序

1. 固定基线：仓库、分支/提交、构建版本、环境、日期、测试账号。
2. 跑通黄金路径并记录每一步输入、输出、状态变化和外部依赖。
3. 逐模块对照：UI → 网络请求/API → 服务逻辑 → 数据持久化 → 日志/监控。
4. 检查非黄金路径：空、错、慢、断、重复、并发、越权、过期、恢复。
5. 检查工程化：安装、构建、配置、测试、发布、回滚、运维文档。
6. 给每一项状态、证据、置信度和影响。

## 审计维度

| 维度 | 重点问题 | 常见“假完成”信号 |
|---|---|---|
| 用户流程 | 是否端到端闭环，返回/刷新/中断后如何恢复 | 只能按固定顺序演示 |
| 页面状态 | 初始、加载、空、成功、失败、无权限、离线 | 只有成功态 |
| 业务规则 | 规则在哪执行，优先级与冲突如何处理 | 前端硬编码、规则散落 |
| 权限 | 身份、角色、资源级授权、审计 | 仅隐藏按钮，无后端校验 |
| API | 契约、错误码、幂等、超时、重试、版本 | Mock 返回、固定 200 |
| 数据 | 模型、约束、来源、质量、保留、迁移 | 临时 JSON/本地存储 |
| 集成 | 凭据、限额、失败降级、沙箱/生产差异 | 个人账号、手工复制 |
| 性能容量 | 负载模型、p95/p99、吞吐、资源上限 | 仅单用户本机验证 |
| 安全隐私 | 威胁、输入校验、密钥、日志脱敏、删除 | 密钥入库、默认管理员 |
| 可靠性 | SLI/SLO、监控、告警、备份、恢复 | 只能靠用户报错发现 |
| 测试 | 单元、集成、端到端、测试数据、可重复性 | 无自动测试或测试被跳过 |
| 发布运维 | 环境、配置、流水线、灰度、回滚、Runbook | 只能由原作者本机启动 |
| 可维护性 | 结构、依赖、许可证、文档、技术债 | 大量 TODO、废弃依赖 |
| 可访问/兼容 | 键盘、读屏、对比度、平台/浏览器 | 仅一台设备可用 |

## 状态判定

- `已实现`：目标路径和关键异常可工作，有持久化/集成证据。
- `部分实现`：主干存在，但有明确缺口或质量不足。
- `占位/Mock`：为演示而存在，未连接真实逻辑或数据。
- `未实现`：没有对应行为或代码。
- `无法验证`：缺权限、环境、依赖或资料；必须写明原因。

## 证据优先级

运行测试/生产等价环境观测 > 可重复的接口与自动测试 > 代码与配置 > 设计/说明文档 > 口头描述。低优先级证据不代表无效，但要降低置信度并安排验证。

## 输出句式

`在 <版本/环境>，执行 <步骤>，观察到 <结果>；证据为 <链接/文件/日志>。因此当前标记为 <状态>，置信度 <高/中/低>。它对 <需求ID/估算/风险> 的影响是 <影响>。`
